The Relativization Barrier

The first barrier is my favourite, because of how simple it is once you see it. The proof uses nothing that we haven't already met. Oracles from Post 36, the "do the opposite" trick from Post 29, and one small game you can play in the figure below.

It was published in 1975 by Theodore Baker, John Gill and Robert Solovay. It's usually called the Baker-Gill-Solovay theorem, or just BGS.

The Theorem​

Baker-Gill-Solovay (1975):

  1. There is an oracle AAA such that PA=NPA\mathcal{P}^A = \mathcal{NP}^APA=NPA.
  2. There is an oracle BBB such that PB≠NPB\mathcal{P}^B \neq \mathcal{NP}^BPB=NPB.

Two imaginary worlds. In one, P equals NP. In the other, it doesn't.

Let me build each one, then explain why having both is a problem.

World A: Where P Equals NP​

The trick here is to choose an oracle so powerful that it drowns out the difference between P\mathcal{P}P and NP\mathcal{NP}NP.

Take AAA to be an oracle for TQBF, the PSPACE-Complete problem from Post 28: deciding quantified formulas with mixed ∃\exists∃ and ∀\forall∀.

  • NP with A is no more than PSPACE
  • P with A is all of PSPACE

A nondeterministic machine with a TQBF oracle, running in polynomial time, can be simulated using only polynomial memory: try each guess one after another (reusing memory, like in Post 28), and whenever it asks the oracle a question, answer it directly, since TQBF itself is in PSPACE\mathcal{PSPACE}PSPACE.

So NPA⊆PSPACE\mathcal{NP}^A \subseteq \mathcal{PSPACE}NPA⊆PSPACE.

TQBF is PSPACE-Complete, so every PSPACE\mathcal{PSPACE}PSPACE problem reduces to it. A normal machine can do the reduction in polynomial time and ask the oracle once.

So PSPACE⊆PA\mathcal{PSPACE} \subseteq \mathcal{P}^APSPACE⊆PA.

Put the two together:

NPA⊆PSPACE⊆PA⊆NPA\mathcal{NP}^A \subseteq \mathcal{PSPACE} \subseteq \mathcal{P}^A \subseteq \mathcal{NP}^ANPA⊆PSPACE⊆PA⊆NPA

The chain starts and ends at the same place, so everything in it is equal. PA=NPA\mathcal{P}^A = \mathcal{NP}^APA=NPA. In this world, the oracle is so strong that guessing gives you nothing extra.

World B: Where P Doesn't Equal NP​

This one is a game, and you can play it.

The oracle BBB is a set of binary strings. For each length nnn, there are 2n2^n2n possible strings of that length. Think of them as 2n2^n2n boxes, and the oracle tells you whether a particular box contains a gem.

Now consider this question:

Is there a gem in any of the length-nnn boxes?

  • Easy with guessing
  • Hard without guessing

A nondeterministic machine with oracle BBB answers this easily. It guesses which box has the gem, and asks the oracle about that one box. If any box has a gem, some guess succeeds.

So this question is in NPB\mathcal{NP}^BNPB.

A normal machine has to open boxes one at a time by asking the oracle. In polynomial time, it can only ask polynomially many questions. With 2n2^n2n boxes, that's a tiny fraction of them.

So here's the plan for building BBB: make the oracle adversarial. Wait until the machine commits to an answer, then put the gem wherever makes its answer wrong.

Try to beat it. You get nnn openings, out of 2n2^n2n boxes. (I'm using nnn as a stand-in for "polynomially many"; the real argument works for any polynomial once nnn is big enough.) Every box you open will be empty. Then answer whether there's a gem anywhere.

You can't win. If you say "a gem exists", the oracle makes every box empty. If you say "all empty", it puts the gem in a box you never opened. Since you can only open a tiny fraction of the boxes, there's always somewhere to hide it.

Building B for real​

The real construction does this against every polynomial-time machine, one at a time, using the same idea as the diagonal argument in Post 29:

  1. List all polynomial-time oracle machines: M1,M2,M3,…M_1, M_2, M_3, \ldotsM1​,M2​,M3​,…
  2. For machine MiM_iMi​, pick a length nnn big enough that MiM_iMi​ can't possibly ask about all 2n2^n2n boxes in its time limit, and bigger than any length used for earlier machines.
  3. Run MiM_iMi​ on the question for length nnn. Whenever it asks about a box that hasn't been decided yet, say "empty".
  4. If MiM_iMi​ answers "a gem exists", leave every box of that length empty. If it answers "all empty", put a gem in some box of that length that it never asked about.

Every machine in the list gets something wrong. So no polynomial-time machine with oracle BBB solves the question, which means it's in NPB\mathcal{NP}^BNPB but not in PB\mathcal{P}^BPB:

PB≠NPB\mathcal{P}^B \neq \mathcal{NP}^BPB=NPB

Why This Is a Barrier​

Here's where the two worlds come together.

A proof technique relativizes if it would still work, unchanged, when every machine in the argument has access to the same oracle. Post 36 explained why many techniques do: simulating one machine inside another, listing all machines, running "do the opposite of machine iii". None of those care whether the machines have an oracle attached.

Now suppose you had a relativizing proof that P≠NP\mathcal{P} \neq \mathcal{NP}P=NP. Because it relativizes, it would also prove PA≠NPA\mathcal{P}^A \neq \mathcal{NP}^APA=NPA. But World A shows that's false. So the proof can't exist.

And suppose you had a relativizing proof that P=NP\mathcal{P} = \mathcal{NP}P=NP. It would also prove PB=NPB\mathcal{P}^B = \mathcal{NP}^BPB=NPB. World B shows that's false too.

The Relativization Barrier

No proof technique that relativizes can settle P vs NP, in either direction.

What This Kills​

When I first read this, I thought, "fine, so some odd techniques don't work". Then I realised which techniques it was talking about.

The diagonalization argument from Post 29, the one that proved P≠EXP\mathcal{P} \neq \mathcal{EXP}P=EXP, relativizes. It only lists machines and simulates them. Put an oracle on everything and the same proof shows PA≠EXPA\mathcal{P}^A \neq \mathcal{EXP}^APA=EXPA for every oracle AAA.

That was the main tool complexity theory had in the early 1970s. It had separated time classes, space classes, and proved the Halting Problem undecidable. The natural hope was that a cleverer diagonalization would separate P\mathcal{P}P from NP\mathcal{NP}NP. BGS showed, in one short paper, that no diagonalization of that standard kind ever could.

I find it oddly beautiful that the theorem uses diagonalization itself (to build World B) to prove that diagonalization isn't enough.

Where We Stand​

What We Have Established

Baker-Gill-Solovay (1975): with oracle AAA = TQBF, PA=NPA\mathcal{P}^A = \mathcal{NP}^APA=NPA, because both equal PSPACE\mathcal{PSPACE}PSPACE. With an adversarially built oracle BBB, PB≠NPB\mathcal{P}^B \neq \mathcal{NP}^BPB=NPB, because a polynomial-time machine can't check enough of the 2n2^n2n boxes to find a hidden gem, while a guessing machine finds it in one question.

A technique relativizes if it works the same with any oracle attached. Since there are oracle worlds where P=NP\mathcal{P} = \mathcal{NP}P=NP and others where P≠NP\mathcal{P} \neq \mathcal{NP}P=NP, no relativizing technique can settle the question. Standard diagonalization relativizes.

Up Next​

BGS doesn't say P vs NP is unsolvable. It says a proof has to use something that doesn't survive having an oracle attached: some fact about how computation actually works, inside the machine.

Post 38 is about what those techniques look like, and the moment in 1990 when one of them proved a famous result that cannot be relativized, and people briefly hoped the barrier had been broken.
