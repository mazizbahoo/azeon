The Class PSPACE

Every class so far has been about time. P\mathcal{P}P: problems you can solve in polynomially many steps. NP\mathcal{NP}NP: problems you can check in polynomially many steps.

But a computer has two resources, not one. It has time, and it has memory. When I was writing code for an assignment last semester, my program didn't run slowly, it crashed because it ran out of memory. That was the first time I really noticed that the two are separate limits.

This post is about the class you get when you limit memory instead of time.

Memory Can Be Reused. Time Can't.​

Here's the single idea that makes space complexity different from time complexity.

Once a second has passed, it's gone. You can't spend it again. But a piece of memory can be written, used, erased and written again, as many times as you like. A whiteboard is not used up by being written on.

So a computer with a small amount of memory can still run for an enormous amount of time, reusing the same few cells over and over.

Space, Formally

The space used by an algorithm is the number of memory cells it uses at the same time, at most. On a Turing machine from Post 3, that's the number of tape cells the head ever visits.

The input itself doesn't count, only the extra working space.

The Class PSPACE

PSPACE\mathcal{PSPACE}PSPACE is the class of yes/no problems that can be solved using a polynomial amount of memory, with no limit on how much time it takes.

NP Fits Inside PSPACE​

Here's the first thing I worked out on my own about this class, and I was quite pleased with myself.

Take any problem in NP\mathcal{NP}NP, say SAT with nnn variables. To solve it with very little memory:

  1. Write the first assignment on the whiteboard: all false.
  2. Check whether it satisfies the formula. That takes polynomial space.
  3. If it does, answer yes. If not, erase it and write the next assignment.
  4. Repeat until you've tried all 2n2^n2n of them.

This takes exponential time: 2n2^n2n assignments. But at any moment, the whiteboard only holds one assignment and the scratch work for checking it. That's polynomial space.

The same trick works for any problem in NP\mathcal{NP}NP: go through every possible certificate, one at a time, reusing the same space. So:

NP⊆PSPACE\mathcal{NP} \subseteq \mathcal{PSPACE}NP⊆PSPACE

And the same trick shows coNP⊆PSPACEco\mathcal{NP} \subseteq \mathcal{PSPACE}coNP⊆PSPACE too: try every certificate, and answer the opposite.

The Problem That Captures PSPACE​

Every class we've met has a "hardest" problem. For NP\mathcal{NP}NP it's SAT. For coNPco\mathcal{NP}coNP it's TAUTOLOGY. For PSPACE\mathcal{PSPACE}PSPACE, it's a combination of the two.

Look at SAT and TAUTOLOGY again, written with the symbols for "there exists" and "for all":

New Symbols: ∃\exists∃ and ∀\forall∀

∃x\exists x∃x means "there exists a value of xxx such that..." It's a backwards E, for Exists.

∀x\forall x∀x means "for all values of xxx..." It's an upside-down A, for All.

  • SAT asks: ∃x1∃x2…∃xn:ϕ\exists x_1 \exists x_2 \ldots \exists x_n : \phi∃x1​∃x2​…∃xn​:ϕ. Is there some assignment that works?
  • TAUTOLOGY asks: ∀x1∀x2…∀xn:ϕ\forall x_1 \forall x_2 \ldots \forall x_n : \phi∀x1​∀x2​…∀xn​:ϕ. Does every assignment work?

What if you're allowed to mix them?

∃x  ∀y  ∃z:ϕ(x,y,z)\exists x \; \forall y \; \exists z : \phi(x, y, z)∃x∀y∃z:ϕ(x,y,z)

"There is some xxx such that, for every yyy, there is some zzz that makes ϕ\phiϕ true."

This is called a quantified Boolean formula, and the problem of deciding whether one is true is called TQBF (True Quantified Boolean Formulas). In 1973, Larry Stockmeyer and Albert Meyer proved that TQBF is PSPACE-Complete: it's in PSPACE\mathcal{PSPACE}PSPACE, and every PSPACE\mathcal{PSPACE}PSPACE problem reduces to it.

A Formula Is a Game​

The thing that made TQBF click for me was reading it as a game between two players.

  • The ∃\exists∃ player wants the formula to be true. They choose the values of the ∃\exists∃ variables.
  • The ∀\forall∀ player wants it to be false. They choose the values of the ∀\forall∀ variables.
  • They take turns, in the order the quantifiers appear.

∃x ∀y ∃z:ϕ\exists x \, \forall y \, \exists z : \phi∃x∀y∃z:ϕ asks: "Does the ∃\exists∃ player have a winning strategy?" Can they pick an xxx such that, whatever yyy the opponent picks, they can still answer with a zzz that makes ϕ\phiϕ true?

And here's how to evaluate it with very little memory. Walk the whole game tree, depth first, holding only the current path in memory. At an ∃\exists∃ node, the value is true if either child is true. At a ∀\forall∀ node, it's true only if both children are.

Step through it and watch the counter. The tree has 8 leaves, and with nnn variables it would have 2n2^n2n. But you only ever hold one path from the root to a leaf in memory, never more than n+1n + 1n+1 nodes. Once a subtree is finished, its value goes up to the parent and the subtree is forgotten.

That's exactly the whiteboard idea. Exponential time, polynomial space.

In this example, the ∃\exists∃ player wins by choosing xxx true. If they choose xxx false, the ∀\forall∀ player picks yyy false and the first clause (x∨y)(x \vee y)(x∨y) can never be satisfied.

Games Live in PSPACE​

Once you see TQBF as a game, a lot of things fall into place. Many two-player games, where the number of moves is limited to polynomially many, are PSPACE-Complete when generalised to bigger boards. Asking "does the first player have a winning strategy?" is asking a quantified formula: "is there a move for me, such that for every reply, there is a move for me, such that..."

Some examples that have been proved PSPACE-Complete:

  • Hex, the board game where players try to connect opposite sides of a diamond-shaped board, generalised to n×nn \times nn×n boards (Stefan Reisch, 1981).
  • Generalised Geography, the word game where each place name has to start with the last letter of the previous one, played on a graph.

And some single-player puzzles too, where the difficulty comes from solutions that can be extremely long:

  • Sokoban, the warehouse puzzle where you push boxes onto targets (Joseph Culberson, 1997).
  • Rush Hour, the sliding car puzzle, generalised to bigger boards (Gary Flake and Eric Baum, 2002).

Why aren't those puzzles simply in NP\mathcal{NP}NP? A solution would be a certificate, but the shortest solution might need exponentially many moves. A certificate that long isn't short, so it doesn't count. They're not known to be in NP\mathcal{NP}NP, and if any PSPACE-Complete problem were, then NP\mathcal{NP}NP would equal PSPACE\mathcal{PSPACE}PSPACE, which almost nobody believes.

Nondeterminism Barely Helps With Space​

Here's a fact that genuinely shocked me.

We spent all of Phase 1 and Phase 2 on whether nondeterminism, the "perfect guessing" machine from Post 4, helps with time. That's P vs NP, and it's unsolved.

For space, the same question was answered in 1970. Walter Savitch proved that anything a nondeterministic machine can do in polynomial space, a deterministic machine can do in polynomial space too. The space needed at most squares, and the square of a polynomial is still a polynomial.

NPSPACE=PSPACE\mathcal{NPSPACE} = \mathcal{PSPACE}NPSPACE=PSPACE

So for memory, "guessing perfectly" gives you essentially nothing. For time, nobody knows. I find it both reassuring and frustrating that the space version of our question has a clean answer and the time version doesn't.

Where PSPACE Sits​

Here's the zoo map again, now with PSPACE\mathcal{PSPACE}PSPACE selected. Everything we've met so far is inside it.

So we have a chain:

P⊆NP⊆PSPACE\mathcal{P} \subseteq \mathcal{NP} \subseteq \mathcal{PSPACE}P⊆NP⊆PSPACE

Is P=PSPACE\mathcal{P} = \mathcal{PSPACE}P=PSPACE? Nobody knows. That's another open problem, and it would be a strange world if it were true. It would mean every PSPACE problem, including finding perfect strategies in generalised games, could be solved in polynomial time. And since NP\mathcal{NP}NP sits in between, P=PSPACE\mathcal{P} = \mathcal{PSPACE}P=PSPACE would immediately give P=NP\mathcal{P} = \mathcal{NP}P=NP as well.

Almost everyone believes P≠PSPACE\mathcal{P} \neq \mathcal{PSPACE}P=PSPACE. But just like P vs NP, nobody can prove it.

Where We Stand​

What We Have Established

PSPACE\mathcal{PSPACE}PSPACE is the class of problems solvable with a polynomial amount of memory and unlimited time. Memory can be reused, so exponential-time search can fit in polynomial space.

NP⊆PSPACE\mathcal{NP} \subseteq \mathcal{PSPACE}NP⊆PSPACE and coNP⊆PSPACEco\mathcal{NP} \subseteq \mathcal{PSPACE}coNP⊆PSPACE, by trying every certificate one at a time.

TQBF, deciding quantified Boolean formulas with mixed ∃\exists∃ and ∀\forall∀, is PSPACE-Complete (Stockmeyer and Meyer, 1973). A quantified formula is a two-player game, which is why generalised games like Hex, and puzzles like Sokoban and Rush Hour, are PSPACE-Complete.

Savitch (1970): NPSPACE=PSPACE\mathcal{NPSPACE} = \mathcal{PSPACE}NPSPACE=PSPACE. For space, nondeterminism barely helps. Whether P=PSPACE\mathcal{P} = \mathcal{PSPACE}P=PSPACE is open.

Up Next​

PSPACE is a class where we can't prove things are hard. Post 29 is about the first class above it where we can.

EXP\mathcal{EXP}EXP is the class of problems solvable in exponential time. And unlike almost everything in this phase, there's a theorem that says, with complete certainty, that some problems in EXP\mathcal{EXP}EXP are not in P\mathcal{P}P. It's one of the only hard separations we have.
